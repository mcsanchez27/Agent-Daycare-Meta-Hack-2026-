# TM-67 projects implementation plan

Source and approved unattended design: https://app.notion.com/p/40463104ef7881b2bee3d06a99505337

Goal: named project containers with saved crew/teammate rosters and independent chats. Use existing Electron/vanilla DOM architecture and plain Node-testable modules, no dependencies. A project stores id, trimmed unique name, roster snapshots and createdAt. Each seeded chat receives fresh member IDs and no vendor sessions. Existing chats and agent-runner.js remain unchanged.

Locked scope: roster edits affect new chats only; deletion unfiles without deleting chats; no moving chats; no changes to folders/MCP/skills. #asks reach only same-project chats. Unfiled chats reach only Unfiled chats. Missing/deleted project IDs resolve as Unfiled, avoiding destructive rewrites of every chat file. Project names compare case-insensitively. Saved roster snapshots preserve persona identity/configuration; membership is chosen only from crew preset or teammates.

Tasks (execute inline, test-first):
- [x] Plain project helpers: roster snapshots, grouping, scope; test isolation, stale IDs, config retention and invalid selection.
- [x] projects.js safe JSON CRUD: queued read-modify-write, duplicate validation, rename/roster update, deletion without touching chats; tests with temporary directories and corrupt files.
- [x] Chats projectId roundtrip/list; main/preload project handlers, project line in fresh/resumed prompts.
- [x] Chooser project creation/edit/delete form and collapsible sidebar groups; seed + chat from roster; persist context and guard #asks at dispatch. Keep ordinary new chats Unfiled.
- [x] Independent review, full Node20 tests, draft PR, Windows/Ubuntu CI. AGENTS.md handoff with manual Windows checks.

Review focus: sessions leaking from roster; concurrent writes dropping projects; deleted references changing prompt or ask scope; empty/error forms; existing chat merge behavior; stale async forms; LF/CRLF tests.
